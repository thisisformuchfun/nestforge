# Contributing to NestForge

Useful contributions make a specific feeder easier to print, assemble, refill, clean or maintain. Start with an exact design ID and revision from [`dist/catalog.json`](dist/catalog.json) so the result can be traced to its files.

## Report a build

Include the design name, downloaded package or commit, printer, nozzle, filament, slicer version/profile, support changes and photos. Describe the actual result: an import, a completed slice, a completed print, measured snap clearance, camera-fit test or installed-load trial are different kinds of evidence.

For a fit issue, show which surfaces interfere or remain loose and provide a measurement where possible. For a camera prototype, name the exact device and accessory; a published bounding box is not a measured camera body. Record release access and focus separately from whether the camera can be inserted.

## Change the website

Use the [development guide](docs/DEVELOPMENT.md) to serve `dist/` and run the existing checks. Keep local links working, preserve keyboard access and label CAD renders and concept diagrams accurately. Retail observations should keep their dates; do not turn a historical offer into a current stock or price claim.

## Change a design

Include the editable source change and explain its purpose. Update the related exports, part metadata, assembly instructions and plate plans together. Run the checks relevant to that revision. Record any validation that was not repeated, particularly native Bambu Studio roundtrip or physical tests.

Preserve third-party licenses, credits and modification notes. Use only assets you have the right to contribute. This repository does not establish a new project-wide license; do not assume an unlicensed asset can be relicensed with a contribution.

Keep speculative concepts separate from the downloadable design catalog until their CAD and print artifacts exist. A new visual treatment alone does not establish manufacturability or field performance.

## Keep reviews focused

Explain the problem, the resulting behavior and how you checked it. Include before/after screenshots for a visible website change and a part-level comparison for a geometry change. Small, complete changes are easier to assess than unrelated changes bundled together.
